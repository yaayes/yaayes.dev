# .impeccable.md
> Design context for yaayes.dev — used to guide all future UI/UX decisions.

## Design Context

### Users
Broadly technical readers — developers, DevOps engineers, SREs, and students learning infrastructure and dev skills at any experience level. They land on the blog to get practical, honest takes on real tools and workflows. The job to be done: learn something useful while genuinely enjoying the read. Reading is as recreational as it is educational, so tone matters as much as accuracy.

### Brand Personality
**Technical, casual, witty.**

The voice is a knowledgeable colleague who knows their stuff but doesn't take themselves too seriously. Humor is a core ingredient, not an afterthought — evidenced by titles like *"Stop Hardcoding Your Passwords, You Animal!"* and self-deprecating jokes about arguing with YAML files. The author is Yassine Sedrani, a DevOps engineer with a distinct personality that should shine through every layer of the interface.

### Aesthetic Direction
- **Terminal-inspired** — The CLI prompt logo (`➜ ~/yaayes.dev` with a blinking cursor) is a deliberate motif, not a gimmick. Lean into it tastefully in navigation, code blocks, and micro-interactions.
- **Primary accent**: Yellow/amber — warm, energetic, distinctly non-corporate.
- **Typography**: Inter for prose; Fira Code / monospace for code and select UI fixtures (logo, tags).
- **Theme**: Light + dark mode, both first-class, system-preference-aware with manual override.
- **Inspiration**: [Tailwind CSS Blog](https://tailwindcss.com/blog) — excellent typography, confident whitespace, strong readability — but with more personality and informality. Also the warm, approachable feel of community blogs (like larabelles.com) without the feminine-coded styling.
- **Anti-reference**: Generic Medium / Hashnode aesthetic — too clean, too corporate, too soulless. This site should feel like it was made by a specific person, not a SaaS template.

### Design Principles

1. **Personality over polish** — Every design choice should feel made by a human with opinions, not generated from a template. Opt for character when in doubt.
2. **Terminal motif, not terminal cosplay** — Use CLI cues (monospace type, amber accent, cursor blink, shell-prompt logo) as recurring motifs. Don't over-hack it into a full retro terminal aesthetic.
3. **Clarity is the feature** — Readable layout, strong typographic hierarchy, and syntax-highlighted code blocks are non-negotiable. Never sacrifice legibility for style.
4. **Earn the humor** — Wit belongs in copy, titles, and micro-interactions; the layout itself stays functional and uncluttered.
5. **Accessible by default** — Target WCAG AA contrast minimums, use semantic HTML, respect `prefers-reduced-motion`, and ensure full keyboard navigability.
